# 独立浏览器与登录维护说明

## 一、核心安全红线

1. **绝不接管日常 Chrome**：工作台绝不连接日常 Chrome 调试端口，绝不读取、复制或修改 `%LocalAppData%\Google\Chrome\User Data`。
2. **分平台物理隔离**：所有自动化浏览器数据独立存放在项目 `browser-profiles/` 目录：
   - `browser-profiles/douyin/`：抖音
   - `browser-profiles/kuaishou/`：快手
   - `browser-profiles/wechat-channels/`：微信视频号
   - `browser-profiles/x/`：X (Twitter)
   - `browser-profiles/youtube/`：YouTube
   - `browser-profiles/other/`：通用动态网页降级
3. **并发互斥锁**：同一时刻同一个平台目录只允许一个任务使用（人工登录窗口开启期间，后台自动采集不会强抢该目录）。
4. **隐私安全**：`browser-profiles/` 已加入 `.gitignore`，日志系统自动脱敏 Cookie / Authorization / Password 字段，绝不向外发送凭证。

## 二、人工扫码 / 登录操作步骤

1. 打开工作台 `http://127.0.0.1:18910` ➔ 左侧 **「浏览器与登录」**。
2. 点击对应平台的 **「打开登录窗口」**，等待独立的自动化 Chromium 窗口弹出。
3. 在独立窗口内完成扫码、手机验证或账号登录。
4. 登录成功后关闭该独立窗口，点击工作台上的 **「检查状态」**，确认状态变为“已登录”。

## 三、登录失效或遇到验证码时

- 后台采集一旦检测到登录过期或滑块验证，会立即停止该平台对应采集并标记 **「需要登录」**，绝不盲目循环重试或尝试破解验证码。
- 你只需重新打开独立登录窗口处理一次，状态会自动持久保存。
