# 数据库与备份说明

## 一、存储引擎与迁移机制

- **数据库引擎**：Node.js 25 原生 `node:sqlite`，开启 `WAL` 日志模式和外键约束，文件默认位于 `data/workbench.db`。
- **版本迁移**：通过 `schema_migrations` 表自动管理结构版本（当前已应用 `v1: initial_schema`）。

## 二、核心数据表

| 表名 | 用途 |
|---|---|
| `categories` | 内容与监控对象分类 |
| `sources` | 监控对象配置、采集频率、最近检查时间和能力状态 |
| `contents` | 去重后的内容主体（含 `platform_item_id`、`canonical_url`、`content_hash` 三层去重） |
| `contents_fts` | SQLite FTS5 全文搜索索引（配合触发器自动同步） |
| `content_metrics` | 互动数据历史快照表（每次互动数据变化追加一条，绝不覆盖旧值） |
| `collections` | 采集任务队列与执行结果记录 |
| `collection_logs` | 每次采集任务的详细步骤日志 |
| `browser_profiles` | 各平台独立浏览器目录、登录状态与需要关注提醒 |
| `app_settings` | 默认频率、浏览器模式与调度开关 |

## 三、数据备份

- **一键热备份**：在工作台 **「系统设置」** 点击 **「立即备份本地数据库」**（或调用 `POST /api/backup`），后端执行 SQLite 原生 `VACUUM INTO` 在 `backups/` 生成完整一致性 `.db` 备份文件。
- **恢复方式**：先运行 `停止工作台.cmd`，将 `backups/workbench-backup-*.db` 复制替换 `data/workbench.db`，再双击 `启动工作台.cmd` 即可。
